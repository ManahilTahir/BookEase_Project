📋 About This Diagram

The Entity Relationship Diagram shows the complete database schema of BookEase. The system has 10 entities and 1 association table (staff_services) that implements the many-to-many relationship between Staff and Service.

Key relationships:

  • User ↔ Staff (1:1) — A user account may optionally link to a staff profile
  • Staff ↔ Service (M:N) — Staff are assigned to multiple services via staff_services
  • Customer → Appointment (1:N) — A customer can have many appointments over time
  • Appointment — The central transaction entity, linking Customer, Staff, Service, and User (creator)

📋 About This Diagram

The Level 0 DFD (context diagram) shows the entire BookEase system as a single process and all external entities (actors) that interact with it. This is the highest-level view of the system.

Four actors interact with the system:

  • Customer — External user who browses services and books appointments via the Streamlit website
  • Staff — Internal specialist who manages appointments, calendar, and customers via the desktop app
  • Admin — Full-access internal user who manages all system configuration, users, and backups
  • Owner — Business owner with all admin permissions except user management

The central SQLite database (D1) stores all data and is accessed by the system for both reading and writing.
